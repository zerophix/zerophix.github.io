03
Pipeline · Deterministic Stages

分析流水线

AnalysisOrchestrator.execute() 的确定性阶段序列；文件级并行发生在扫描阶段，编排本身保持单线程有序。

0

装配扫描期符号求解

runId（yyyyMMdd-HHmmss）→ attachScanTimeSymbolResolver()：ClasspathPlan 单线程构建一次，再安装每线程的 JavaSymbolSolver 工厂（DEC-059/060），供后续并行扫描使用。

1

扫描 Java 源码 SourceCodeScanner.scan()

ForkJoinPool(min(CPU 核数, 8)) 并行解析；按 Path 排序保证图结构与环检测结果可复现；解析失败计入 scan_stats。

2

扫描非 Java 资产 ProjectFileScanner

pom.xml、MyBatis XML mapper、Dockerfile、配置文件等，形成 project_assets。

3

跨文件关系发现 RelationEngine.discoverRelations

复用唯一一份 CallGraphBuilder（DEC-034，不建第二张图），跑 6 条发现通道。

4

质量规则分析 QualityAnalyzer.analyzeWithClassAssets

RuleRegistry 注册 480 条规则 → RuleEngine 逐类执行 → 重复代码检测 → 特殊 CFG / 污点 / 架构规则 → 位置去重 + 严重度校准。增量模式只跑变更文件。

5

项目类型识别 ProjectTypeDetector.detect

判定 spring / spring-boot / 普通 Java 等，决定后续框架分析分支。

6

框架专项分析 FrameworkAnalyzer

Spring 分支：Bean 依赖图与环、HTTP 端点、@Transactional 边界、AOP、Security 配置（可扩展 MyBatis / Dubbo）。

7

核心增强分析 CoreAnalysisEngine / IncrementalAnalysisEngine

全量：符号解析 → 接口多态扫描 → 全局调用图 → 字节码精化 → 调用链追踪 → 数据流 → 架构分层 → 技术债。增量：按变更文件重算并合并。

8

架构分层检查 ArchitectureLayerAnalyzer

包名模式分层 → 依赖白名单比对 → LayerViolation 列表。

9

装配结果容器 assembleResults

schema_version 1.0.0 / analyzer_version 3.5.0；合并资产、依赖、问题、调用边、scan_stats（解析覆盖率）、缓存溯源。

10

设计模式 + 领域语义 DesignPatternDetector / SemanticRecognizer

30 个模式检测器并行打标；语义识别给出角色 / 意图 / 领域词 / 状态机。

11

生成报告 + 语义词典 + 广播完成 ReportGenerator

HTML → 技术债 → 门禁评估 → summary.json → full.json → glossary_raw.json → SARIF → semantic_dictionary.json → WebSocket analysisComplete。

并行与确定性

  • 扫描并行：ForkJoinPool(min(cores, 8))，增量路径另有 changedFiles.parallelStream()。
  • 符号求解：语言级别为线程局部配置，JavaParserConfig.ensureThreadConfigured() 保证 worker 线程配置一致。
  • 确定性：源文件按路径排序、调用链 callee 按字典序排序 → 图与环、链路输出字节级可复现。
  • 规则引擎：RuleEngine.runParallel() 存在（按类并行），当前主路径调用的是串行 run()。

05
Algorithms · Spec Sheets

涉及的算法

全部基于 JavaParser AST，而非正则字符串匹配。以下每张规格卡给出：问题 → 数据结构 → 算法策略 → 复杂度 / 参数 → 实现类。

Alg. 01 — Call Graph

调用图构建与链路追踪

CallGraphBuilder · CrossFileCallResolver · InterfaceResolver · BytecodeCallGraphBuilder · CallChainTracer
数据结构
双向邻接表：Map<String,Set<String>> callEdges / reverseCallEdges，方法键为 class:method:signature；另有 declaredMethods、pendingFallbacks（延后裁决的启发式边）。
解析策略
优先 JavaParser SymbolSolver；失败时走启发式回退链：this/super → 局部变量与参数 → 字段 → 类名（静态）→ 方法链返回类型（foo().bar() 递归）→ import 表 / 同包。
方法匹配
先参数个数、再参数类型兼容（含装箱与集合规则）；new X() 恒定产生 CONSTRUCTOR_CALL 边。
多态分派
InterfaceResolver 扫描接口 / 实现 / 继承树，resolveDispatchTargets 用 BFS + visited 集合求接口与子类的传递闭包；只在目标确实声明该方法时才挂边，避免悬空边。
边界与字节码
ExternalLibrarySignatureDB 标注外部副作用（如 INSERT pay_order）作为链路语义终点；有 target/classes 时用 ASM 精化边（isResolved=true）。
图算法
环检测 = DFS + recursionStack + parentMap 重建环路；调用深度 = 记忆化 DFS 最长路；热点方法 = 入度排序（reverseEdges）。
链路追踪
CallChainTracer.traceDFS：DFS + 路径内环检测 + best-depth 剪枝（节点仅在被更深到达时才重展开，把指数级展开压到近多项式）+ 每入口链路预算。
复杂度
建图 O(V+E)，邻接查询 O(1)；环检测 / 深度 O(V+E)；默认追踪深度 maxTraceDepth=10（0=不限）。
邻接表BFS 传递闭包DFS 环检测记忆化最长路入度热点排序
Alg. 02 — Control Flow

控制流图（CFG）与支配关系

domain/analysis/cfg/CFGBuilder.java（772 行）
数据结构
CFGNode 8 种类型：ENTRY / EXIT / BASIC_BLOCK / CONDITIONAL / SWITCH / TRY / CATCH / FINALLY，含 successors/predecessors（LinkedHashSet，保序）与支配字段；CFGEdge 带边类型。
构造状态
Deque<LoopContext> loopStack（break/continue 含标签）、Deque<CFGNode> finallyStack、当前 try/catch/finally 槽位，逐语句构造 if/for/while/do/switch/try/synchronized/foreach。
异常边
语句按 canThrowException(stmt) 生成指向匹配 catch 节点（或异常出口）的边，try-catch-finally 全覆盖。
短路与三元
&& / || 用 buildShortCircuit 展开真假分支；lambda 视为原子块。
支配树
经典迭代数据流不动点：dom(n) = {n} ∪ ⋂ dom(p)，悲观初始化为全集，收敛后成对包含关系提取立即支配者。
度量
真实圈复杂度 M = E − N + 2P（McCabe），另有不可达节点、路径枚举、DOT 导出。
消费者
TrueCyclomaticComplexity / UnreachableCode / ResourceLeakPath / ExceptionHandlingPath 4 条路径型规则。
迭代不动点支配树M=E−N+2P异常边建模
Alg. 03 — Data Flow

数据流图与到达定义

DataFlowGraph · ControlFlowAwareDataFlowGraph
两遍构建
第一遍为每条语句收集 defs / uses（表达式 / return / if / while / for / foreach），第二遍按 def→use 建边；索引 defs/uses 映射 + IdentityHashMap<Statement,DFGNode>。
控制流感知
叠加顺序 / 分支控制流边后计算到达定义（经典迭代不动点）：IN[n]=⋃OUT[p]，OUT[n]=gen[n] ∪ (IN[n]−kill[n])，迭代至不动点（上限 100 次）。
结果
由到达定义导出 def-use 链 → 路径敏感、分支感知的污点传播，循环处理正确，误报低于正则型引擎。
复杂度
语句数 n、定义数 d 下，迭代次数受循环回边限制（上限 100），单轮 O(E·d)。
到达定义def-use 链分支敏感
Alg. 04 — Taint Analysis

污点分析（跨方法）

TaintEngine · EnhancedTaintEngine · CrossMethodDataFlowGraph · CrossMethodTaintAnalyzer
源 / 汇 / 净化
Source：getParameter / getHeader / readLine / getenv / args[…；Sink：executeQuery / prepareStatement / Runtime.exec / new File / evaluate / openConnection…；Sanitizer：escapeSql / PreparedStatement / URLEncoder.encode…
引擎演进
TaintEngine（正则表，预编译 Pattern[]，快但粗）→ EnhancedTaintEngine（source→标签、sink→漏洞类型映射，走 ControlFlowAwareDataFlowGraph 做路径敏感跟踪）。
跨方法图
CrossMethodDataFlowGraph：每个方法一份 CFG-DFG，按调用图叠加 PARAM / RETURN 方法间边，METHOD_ENTRY / METHOD_EXIT 作包装节点。
跨方法追踪
traceTaint：递归 DFS + visitedMethods + maxMethodDepth；traceFromSource 在调用图上 DFS，进入时加入 visited、退出时移除（完整路径回溯），并把污点变量映射到被调方形参。
输出
有序 TaintStep 序列构成 CrossMethodTaintPath，末尾按位置去重；规则侧由 TaintFlowRule / EnhancedTaintFlowRule / CrossMethodTaintRule 承接。
SQL 注入 / RCE 路径路径回溯 DFS参数映射
Alg. 05 — Clone Detection

重复代码检测

quality/DuplicateCodeDetector.java
方法
Token 序列滑动窗口（不是 AST 哈希）：body 按非标识符切分 → 小写化 → 剔除长度 ≤1 与噪声词（return/if/else/for/while/new/this/null/true/false）。
索引
每 10 个 token 一个窗口，串成 key 放进 TreeMap<String,List<TokenLocation>> —— 有序桶保证与扫描完成顺序无关的确定性输出。
判定
桶内 ≥2 个位置 → 报 RSPEC-888 Duplicated code block（MAJOR）；锚点取序最小位置，每个 class.method 只报一次。
复杂度
token 数 T → O(T) 窗口入桶 + O(B log B) 排序，B 为桶数。
滑动窗口指纹确定性输出
Alg. 06 — Incremental Cache

增量分析与缓存

IncrementalAnalysisEngine · IncrementalCache · CacheKeyResolver · CacheLocation
缓存键
SHA-256(文件字节) + ":" + analyzerVersion；命中即比对 hash:version，统计 hits/misses/hitRate。
存储
单文件 Gson JSON：{scan_date, analyzer_version, files:{<relpath>:{hash,class_count,method_count,field_count,cachedAssets[]}}, totals}。
失效
两级：整表失效 CACHE_VERSION = "2.3.0"（资产结构变更必须 bump，Javadoc 记录每次原因）；文件失效 内容哈希变化。normalizeNumbers() 修复 Gson Double 类型回读，否则规则内 (int) 强转异常会让发现静默丢失。
位置
默认 ~/.glossary-analyzer/cache/<项目>-<路径哈希>（环境变量 GLOSSARY_ANALYZER_CACHE_DIR 改根），指进被分析仓库会告警。
增量流程
移除变更文件旧数据 → 重扫 → 更新类资产索引 → 重建 import 表 → 增量建图 → 接口分析 → 数据流 → 分层 → 技术债 → 合并摘要；--depth 依赖闭包默认 2 层。
SHA-256 指纹版本化失效仓库外缓存
Alg. 07 — Pattern Mining

设计模式识别

DesignPatternDetector + 30 个 AbstractPatternDetector 子类
输入

策略

覆盖

去重

启发式 + 置信度30 个检测器

Alg. 09 — Rule Engine & Gate

规则引擎与质量门禁

RuleEngine · RuleRegistry · QualityGate · TechnicalDebtEstimator
执行
逐类 × 逐规则；isRuleApplicable() 按标签预筛避免全量扫描；记录每规则命中数与耗时（ruleExecutionTimesMs）；单规则异常吞为 warning 不中断。

07
Quality Gate · Technical Debt

质量门禁与技术债

默认 advisory（报告阈值、不硬阻断），CI 需要硬阻断时显式切换 strict + fail-on-gate。

密度上限 density

  • CRITICAL：0.5 / KLOC
  • MAJOR：15 / KLOC
  • 非 INFO 合计：50 / KLOC
  • 绝对值可用 -1 关闭，改走密度

结构上限 structural

  • 架构违规 ≤ 5
  • 数据流问题 ≤ 10
  • 循环调用 ≤ 5
  • 接口问题 ≤ 20

比率与基线 ratio / baseline

  • 技术债占比 ≤ 5%
  • 债务小时数上限默认 0（走占比）
  • 存在 quality-baseline.json 时自动切回归轨：不得劣于基线

三种模式

模式判定典型用法
advisory（默认）恒 passed=true，reasons 前缀 ADVISORY: thresholds not met (non-blocking)本地开发 / 首次接入
lenient仅 CRITICAL 超上限才失败存量项目渐进收紧
strict + --fail-on-gate全部阈值判定，超限 exit 1CI 硬阻断

QualityGate.toGitHubCheckJson() 可直接产出 GitHub Check Run 负载；技术债评级 A(≤5%) / B(≤10%) / C(≤20%) / D(≤50%) / E(>50%)。
