01
Workflow · 八道工序

从「有一个想法」到「可以交付」
中间要走的完整流水线

每道工序都有明确产出物。跳过任何一道，问题都会在后面的工序里加倍奉还——最常见的是跳过「定问题」和「建系统」。

01 定问题→02 收灵感→03 搭骨架→ 04 画线框→05 建系统→06 出视觉→ 07 加交互→08 走查交付
01

定问题 Define

明确用户是谁、在什么场景用、怎样算成功，把目标写成一句话。这一步决定后面所有取舍的标准。

产出 · 目标卡 / 用户画像 工具 · 纸笔 / 文档 坑 · 没定目标就打开画布
02

收灵感 Reference

建情绪板，拆解 3 个同类产品的「结构与流程」，而不是截几张好看的图。收藏时标注好它哪里值得抄。

产出 · 情绪板 / 参考清单 工具 · Behance · Mobbin · Pinterest 坑 · 只收集好看的，忘了好用的
03

搭骨架 Structure

画站点地图与用户流程，穷举页面清单与状态清单（默认 / 加载 / 空 / 错误 / 成功 / 权限）。先结构，后像素。

产出 · 信息架构 / 流程图 工具 · FigJam · Whimsical 坑 · 漏掉空态、错误态、权限态
04

画线框 Wireframe

低保真排布信息层级，用真实文案占位而不是 Lorem ipsum——文案长度会直接决定排版是否成立。

产出 · 低保真线框稿 工具 · Figma · 纸笔 坑 · 线框阶段就上色，问题混在一起
05

建系统 System

定义设计 Token：色板与语义色、字阶、间距刻度、圆角、阴影、动效曲线；再把组件按状态矩阵做一遍规范。

产出 · Style Tile / Token 表 工具 · Figma Variables 坑 · 同一种按钮画了五遍五个样
06

出视觉 Interface

高保真页面，覆盖全部状态与断点。用真实数据排版：超长文本、空值、极端数字都得排得下。

产出 · 高保真设计稿 工具 · Figma 坑 · 用完美假数据排版，上线即崩
07

加交互 Prototype

原型走通主流程，动效统一曲线与时长（如 180ms / 320ms 两档）。动效为「解释状态变化」存在，不为炫技。

产出 · 可点原型 / 动效规范 工具 · Figma 原型 · Rive · ProtoPie 坑 · 动效时长随手写，节奏混乱
08

走查交付 Handoff

无障碍与响应式走查，输出标注链接、切图、Token JSON；开发完成后按清单核对还原度，记录差异。

产出 · 走查清单 / 交付包 工具 · Stark · axe · Dev Mode 坑 · 只验理想路径；口头交付不落文档
02
Components · 九大组件族

一个界面拆到底
就是这九族零件

把它当成自检清单：每族里的条目，你的设计稿覆盖了几个？每族末尾的一句话是该族的设计要点。

FAMILY 01

导航Navigation

  • 顶栏
  • 标签页
  • 侧栏
  • 面包屑
  • 分页
  • 步骤条
  • 返回
  • 锚点
  • 命令面板
要点：用户随时能回答"我在哪、能去哪、怎么回"；任何页面三次点击内可达。
FAMILY 02

按钮Actions

  • 主按钮
  • 次按钮
  • 幽灵按钮
  • 危险按钮
  • 图标按钮
  • 按钮组
  • 拆分按钮
  • 加载态
  • 禁用态
要点：一页只留一个主按钮；危险操作与主操作物理隔开，避免误触。
FAMILY 03

表单Forms

  • 输入框
  • 文本域
  • 下拉
  • 多选
  • 级联
  • 单选
  • 开关
  • 滑块
  • 日期
  • 文件上传
  • 搜索框
  • 评分
  • 校验提示
要点：每个字段四态齐全（默认 / 聚焦 / 错误 / 禁用），标签永不被 placeholder 取代。
FAMILY 04

数据展示Data

  • 表格
  • 列表
  • 卡片
  • 徽章
  • 标签
  • 进度
  • 统计数字
  • 时间线
  • 树
  • 骨架屏
  • 空状态
要点：假数据骗人——用真实长文本、极端值、空值来检验排版与截断策略。
FAMILY 05

反馈Feedback

  • Toast
  • Alert
  • 对话框
  • 抽屉
  • 气泡卡
  • Tooltip
  • 全局进度
  • 结果页
  • 撤销提示
要点：错误信息要说"怎么办"，不要只说"出错了"；反馈必须出现在用户视线附近。
FAMILY 06

图表Charts

  • 折线
  • 柱状
  • 饼 / 环
  • 面积
  • 散点
  • 仪表盘
  • 迷你图
  • 漏斗
  • 地图
要点：一图一结论：先想清楚要用户看到什么，再选图形；坐标轴与图例不能缺席。
FAMILY 07

多媒体Media

  • 灯箱
  • 轮播
  • 视频
  • 音频播放器
  • 波形
  • 头像
  • 封面
  • 画廊
要点：占位 / 加载 / 失败三态齐全；控制条必须可键盘操作、可暂停。
FAMILY 08

布局Layout

  • 栅格
  • 分栏
  • 粘性
  • 折叠面板
  • 瀑布流
  • 分隔线
  • 滚动容器
  • 断点
要点：间距用 4 / 8 的倍数成体系；至少设计移动、平板、桌面三个断点。
FAMILY 09

业务模式Patterns

  • 上传队列
  • 筛选器
  • 搜索结果
  • 详情页
  • 新手引导
  • 评论
  • 聊天
  • 工单
  • 拖拽排序
要点：拆解成熟产品的真实流程再改造，比凭空发明一套交互可靠得多。

04
Kit · 开工材料包

动手画之前
先把这四包材料备齐

红色勾选的六项是"没有就别开工"的硬材料，其余是让过程更顺的软材料。

内容素材Content

  • 真实文案（拒绝 Lorem ipsum，含超长句）
  • 真实数据（极端值、空值、小数、零）
  • 图片与插画选型清单
  • 图标风格定稿（线性 / 面性 / 双色）
  • 品牌素材（Logo、品牌色、字体授权文件）

结构骨架Structure

  • 页面清单与用户流程图
  • 状态清单（默认·加载·空·错误·成功·权限）
  • 断点策略（移动 · 平板 · 桌面）
  • 导航层级与返回逻辑
  • 异常与边界场景列表

设计系统System

  • 色板 + 语义色（成功/警告/错误/信息）
  • 字阶与行高（标题 / 正文 / 注释三档起）
  • 间距刻度（4 或 8 的倍数）
  • 圆角、阴影、描边规范
  • 动效曲线与时长档位

交付验收Handoff

  • 设计 Token 导出（JSON / CSS 变量）
  • 标注链接（Dev Mode / 蓝湖）
  • 切图与图标源文件（SVG 优先）
  • 无障碍目标（对比度 4.5:1、键盘可达）
  • 还原走查清单与差异记录表
05
Pitfalls · 避坑清单

新手最常踩的
八个坑

每一条都对应前面某道工序的"坑"位，交付前对照着删一遍。

  • ×
    Lorem ipsum 掩盖排版问题——文案一换成真实的，卡片高度就塌了。
  • ×
    组件只画理想态——等于没画。加载、空、错误、禁用、超长才是设计的主战场。
  • ×
    圆角与间距随手定——同一页面出现 5 种圆角、7 种间距，视觉立刻显乱。
  • ×
    三种以上主字体打架——显示、正文、等宽各一款，足矣。
  • ×
    动效时长随手写——没有统一曲线与档位，整个产品会显得"晃"。
  • ×
    只在一个宽度下设计——窄屏一放，表格与导航全崩；断点要提前规划。
  • ×
    对比度不达 4.5:1——浅灰小字"高级感"的代价是用户看不清。
  • ×
    装饰比内容抢眼——氛围层永远服务于信息，喧宾夺主就是失败。
