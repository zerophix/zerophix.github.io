Track A · 功能型产品

侧重「任务」：帮用户把事做完

工具、后台、交易类产品。评价标准是效率、准确率与完成率。工作流重心落在范围层与框架层——功能规格和交互流程决定成败，视觉只是信任背书。

Track B · 信息型产品

侧重「内容」：帮用户找到并看懂

媒体、官网、文档、社区类产品。评价标准是可寻性与可读性。工作流重心落在结构层与表现层——信息架构和视觉层级决定成败，内容本身就是产品。

01ST

Strategy · 战略层决定「为什么做」的地基

我们为什么做？为谁做？怎么算成功？
工作流 · Workflow

  1. 明确产品目标与商业目标

    先回答"公司要什么、用户要什么"，把模糊的愿景收敛成一句可验证的目标陈述，定义北极星指标。

    → 产出：产品愿景陈述 / 指标定义

  2. 用户研究：访谈 / 问卷 / 观察

    定性访谈挖动机，定量问卷验规模，实地观察看真实行为。注意区分用户"说的"和"做的"。

    → 产出：访谈记录 / 问卷数据 / 观察笔记

  3. 竞品与市场分析

    选 3–5 个直接与间接竞品，拆解功能矩阵、体验路径与定价，找到差异化空间。

    → 产出：竞品分析报告 / SWOT

  4. 构建用户画像与场景

    把研究数据聚类成 2–3 个典型 Persona，配以使用场景和痛点清单，作为后续所有决策的裁判。

    → 产出：Persona / 用户旅程草图

  5. 定义成功标准

    为每个目标设定可衡量的验收指标（转化率、留存、任务完成时长、满意度 CSAT/SUS）。

    → 产出：成功指标表
产品愿景 用户画像 Persona 竞品分析报告 用户研究纪要 成功指标
避坑 · Pitfall 最常见的失败是跳过这一层直接画原型。没有战略层的"设计"只是装饰——做得再漂亮，也无法回答"为什么用户要用它"。

02ND

Scope · 范围层把战略翻译成「做什么」

做哪些功能与内容？边界在哪里？
工作流 · Workflow

  1. 需求收集与整理

    来自用户反馈、业务方、数据分析与竞品借鉴。用用户故事（As a… I want… So that…）统一语言。

    → 产出：需求池 / 用户故事列表

  2. 需求分类：功能需求 vs 内容需求

    功能型产品写功能规格（做什么、怎么算完成）；信息型产品写内容清单（谁提供、多久更新、什么格式）。

    → 产出：功能规格 / 内容清单

  3. 优先级排序

    用 Kano 模型分基本型/期望型/兴奋型需求，用 MoSCoW 或 RICE 打分排出实现顺序。

    → 产出：优先级矩阵

  4. 划定 MVP 边界

    明确"这次一定做 / 可以延后 / 明确不做"。范围失控是项目失败的头号原因，写下来才算数。

    → 产出：MVP 范围说明

  5. 制定版本路线图

    把需求映射到版本节奏（V1 / V1.5 / V2），让所有人对节奏有统一预期。

    → 产出：Roadmap
PRD / 需求文档 功能清单 内容清单 优先级矩阵 版本路线图
避坑 · Pitfall "先都做上，后面再砍"是灾难的开始。范围层的核心能力是取舍——写清楚不做什么，比写清楚做什么更难、也更重要。

03RD

Structure · 结构层信息如何组织、用户如何流转

内容怎么分类？用户从 A 怎么走到 B？
工作流 · Workflow

  1. 绘制用户流程图（User Flow）

    以任务为主角，画出从入口到目标的关键路径，标注每一步的决策点和退出点。

    → 产出：任务流程图

  2. 设计信息架构（IA）

    内容型产品做站点地图与分类体系；核心是层级深度与广度的平衡——一般不超过 3 次点击到达内容。

    → 产出：站点地图 / 树状结构

  3. 卡片分类验证（Card Sorting）

    让用户自己给内容分组，验证你的分类是否符合用户心智模型，而非你的组织架构。

    → 产出：分类校验报告

  4. 定义导航体系

    全局导航、局部导航、辅助导航、面包屑各司其职，确保用户永远"知道自己在哪、能去哪"。

    → 产出：导航结构图

  5. 补全状态与异常流程

    加载中、空状态、错误、权限不足、断网……正常路径只占 20%，异常状态才是体验的分水岭。

    → 产出：状态流转图
用户流程图 站点地图 信息架构图 导航结构 状态流转表
避坑 · Pitfall 用公司部门架构去做产品信息架构，是业余与专业的分界线。用户不关心你的组织架构，只关心"我要找的东西在哪"。

04TH

Skeleton · 框架层界面、导航与信息的排布

屏幕上放什么、放在哪、怎么交互？
工作流 · Workflow

  1. 纸面草图先行

    5 分钟一张，快速探索 3 种以上布局方案。低精度才能低成本试错，别过早纠结像素。

    → 产出：草图方案若干

  2. 低保真线框图

    确定页面区块、控件类型与相对层级。线框不带颜色，强迫大家讨论结构而非"好不好看"。

    → 产出：线框图 Wireframes

  3. 界面设计与栅格系统

    建立 8pt 间距体系、栅格列数与断点规则，让布局有可复用的节奏。

    → 产出：布局栅格规范

  4. 交互原型（可点击）

    把关键路径串成可操作原型，补充转场、反馈、动效时长等交互细节。

    → 产出：可点击原型

  5. 可用性测试与迭代

    找 5 位目标用户完成真实任务，记录卡点。测完改、改完再测，两轮迭代质量翻倍。

    → 产出：可用性测试报告
低保真线框 交互原型 栅格与布局规范 交互说明 可用性测试报告
避坑 · Pitfall 用高保真视觉稿代替可用性测试：用户会因为"好看"而客气，看不清结构问题。低保真原型测出的问题才真实。

05TH

Surface · 表现层视觉传达与最终感知

看起来什么感觉？是否传达了战略？
工作流 · Workflow

  1. 情绪板（Moodboard）

    用图片、色彩、材质拼出 2–3 种视觉方向，先对"感觉"达成共识，再谈规范。

    → 产出：情绪板 / 视觉关键词

  2. 建立色彩体系

    主色（品牌）、中性色（文字与背景梯度）、语义色（成功/警告/错误），全部定义色值与使用场景。

    → 产出：色彩规范

  3. 字体与排版系统

    确定字族、字阶（Type Scale）、行高与字重规则。中英文混排注意等宽对齐与标点挤压。

    → 产出：排版规范

  4. 图标与插画规范

    统一线宽、圆角、栅格尺寸（如 24px 基准）；插画风格与品牌调性一致，避免混搭。

    → 产出：图标库 / 插画风格

  5. 视觉走查与交付（Design QA）

    开发还原度走查：间距、色值、状态、暗色模式、多语言长度。交付时配标注与切图。

    → 产出：走查清单 / 标注稿
情绪板 视觉规范 UI Kit 图标与插画规范 标注与切图
避坑 · Pitfall 表现层不能"拯救"下层问题：视觉再惊艳，如果战略模糊、流程不顺，用户依然会流失。先对，再美。
